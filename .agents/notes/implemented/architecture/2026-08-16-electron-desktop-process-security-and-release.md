# Agent Note: Electron Desktop process authority, lifecycle, and release identity

Status: implemented

English | [中文](2026-08-16-electron-desktop-process-security-and-release.zh.md)

## Problem

Running the shared GUI inside Electron introduces authorities that the Web product does not have: native windows and dialogs, an installed package filesystem, OS process control, signing and update APIs, and a local Host that shares durable state with CLI/Web processes. Putting the Harness Host in Main would combine untrusted Renderer input, native UI policy, plugins, storage, and long-running agent work in the process Electron expects to remain responsive. Exposing a generic Preload bridge or starting a private HTTP server would recreate a broad remote-control interface and weaken the no-listener goal. Treating process exit as clean shutdown would also let an update or crash race session flush and lease release.

The installable product needs one release identity across application code, native dependencies, installers, update metadata, hashes, compliance materials, and diagnostics. Signing a developer-built tree after packaging or publishing mutable update metadata before every target exists would make the bytes that users run differ from the bytes the repository verified.

## Decision

Desktop assigns one authority to each Electron role. Main owns window/navigation/permission policy, protocol resources, sender validation, dialogs, updates, diagnostics orchestration, and the lifecycle supervisor. Utility owns the Harness profile, business API dispatcher, plugins, persistence, native providers, exports, logs, and the canonical-home Host lease. Preload exposes one frozen, versioned API with a closed command union. Renderer runs the shared GUI and IPC carrier with no Node or raw Electron object. Main forwards validated outer frames and generation-bound ports without parsing business request or response bodies.

The data protocol is a closed discriminated union over a transferred `MessagePort`. Every control and data registration includes the supervisor generation; replacement closes old ports and rejects late frames. Request limits are configurable and validated at load. Unary bodies and stream bodies use pull-driven chunks with one outstanding pull and one in-flight chunk; the Renderer coalesces smaller upstream chunks into at most 1 MiB before structured cloning, so browser-sized 64 KiB file chunks do not each incur a cross-process copy. Cancellation propagates in both directions, and every registry settles once on close. A request that may have crossed into a failed Utility returns outcome unknown and is not automatically replayed.

Main registers `app://localhost` as the only Renderer origin. The resource map begins empty and becomes usable only from Utility's strict client resource manifest. It accepts packaged core resources and declared client bundles, rejects unsupported methods, traversal/encoded separators/NULs, unknown ids/revisions, and symlink escapes, and applies per-resource content types plus a CSP with no remote script, `unsafe-eval`, or network connection source. BrowserWindow enables sandbox and context isolation, disables Node integration, denies permissions/navigation/popups by default, and delegates only allowlisted external schemes to the OS. The window factory revalidates its single WebPreferences object before construction; Renderer revalidates the exact origin, Node-global isolation, and frozen bridge keys before GUI boot. Every Main IPC command checks the live WebContents, main frame, exact origin, generation, and schema.

Desktop replaces the shared API Gateway row with a subclass that changes only native-path defaults. A raw `host.openPath` payload is realpath-resolved in Utility and accepted only inside a registered canonical Workspace; a symlink escape or missing target fails before Main receives it. Settings and Agent Preset actions carry no path from Renderer and therefore keep their Host-resolved targets. Every accepted default-application or text-editor handoff crosses the strict control protocol under a one-shot generation-bound operation id; Main owns the OS call, while cancellation, duplicate ids, shutdown, and Utility replacement remove the pending operation without exposing an arbitrary Main IPC path method.

The supervisor treats starting, ready, degraded, recovering, circuit-open, stopping, and stopped as distinct states. Utility ready requires protocol/version agreement, matching generation/application version, a complete boot/resource manifest, profile activation, and the Host lease. POSIX uses an owner-only directory plus safely classified Unix socket; Windows uses an owner-only named pipe with an explicit DACL. The lease is acquired in Utility before business plugins, so Desktop, CLI, and Web compete at the actual writer. A Utility crash closes the failed generation and retries with bounded exponential backoff plus symmetric jitter; base, maximum, and jitter all come from strict app-private configuration validated at load. Renderer recovery has an independent failure budget: opening its circuit replaces only the window with recovery UI, preserves the healthy Utility and unrelated Host work, and a manual retry attaches a fresh data port to the same Utility generation.

Normal shutdown stops new operations, cancels generation registries, asks Utility to flush/dispose/release, and waits for `host/quiescent`. Timeout escalation terminates and then kills the child without labelling the result quiescent. Update installation uses the same path and calls the native installer only after quiescence; otherwise it aborts the install attempt and leaves the current application unchanged.

The production updater origin, application id, and release page are compile-time constants. Main derives stable/canary from the application semantic version, validates monotonic target version, channel, and HTTPS origin, and exposes only a closed state to Renderer. macOS/Windows use Electron's native updater; Linux reports package-manager/release-page guidance. Download and install approval remain separate.

The build uses a materialized production closure shared with the Python executable staging rules, removes symlinks and wrong native variants, rebuilds native dependencies for Electron, packages core code in ASAR, unpacks only approved native files, and burns restrictive fuses. Final installer bytes derive update metadata, SHA-256 sums, CycloneDX SBOM, exact notices, license, build identity, and provenance. Legal text for an external dependency must come from the package or an audited supplement that fixes package identity, version, and content hash; an unknown missing case blocks material generation. The native CI matrix builds macOS arm64/x64, Windows x64, and Linux x64; signing/notarization runs only in the protected environment, verifies the final application and installers, and never publishes a remote channel. Publication remains an explicit human boundary after a complete matrix.

Final-maker acceptance installs from the `.dmg`, Squirrel, `.deb`, or `.rpm`, starts behind a blocking proxy with no API key, and verifies the real process tree, no listening port, Renderer/Utility fault recovery and independent circuit domains, forced Main termination followed by same-home recovery, quiescent shutdown, and system uninstall. It verifies removal, reinstalls the same maker artifact, repeats the packaged startup smoke, and uninstalls again. While the installed Utility holds the home lease, a second packaged Desktop must complete the single-instance handoff while the first process remains alive, and the real headless CLI and Web profile must both lose the same-home race before mounting plugins. Stable snapshots prove that no losing process added, removed, or changed sessions, Workspace storage, attachments, settings, or credentials. Native probes directly load every unpacked `.node` and exercise sharp, Koffi, PTY, ripgrep, and Landlock where supported. A shared gate measures the extra p95 round-trip cost of the production carrier/Host bridge with 1 KiB request and response bodies against the same direct dispatcher and requires at most 10 ms. The installed four-target endurance matrix repeats that measurement with 20 warmups and 100 samples through the final Renderer, Preload-transferred Electron `MessagePort`, and Utility handler. macOS jobs tamper only with a disposable application copy, restore a valid ad-hoc signature, and require embedded ASAR integrity to reject startup before Renderer ready. The protected matrix drives one cancelled and one successful archive of at least 1 GiB through the installed Renderer/Preload/Main/Utility chain; an explicit CI-and-packaged-only Main gate fixes the target to an owner-only directory in the disposable home, and an acceptance plugin supplies bounded synthetic persistence, lineage, and attachment sources to the production Session export handler without adding a Renderer command. The gate validates central-directory entries and a streamed SHA-256. After the signed matrix completes, each endurance target uses an external loopback provider, cancels every fifth stream, replaces Renderer after each 100 requests to rotate the actual port, samples the installed process tree for 60 minutes, and requires aggregate Utility bridge/registry/reader/native-operation counts to return to baseline. These automated gates produce candidate evidence but do not replace the final-installed GUI acceptance record, an upgrade from the preceding signed version, canary observation, or human publication approval.

The idle-memory release check samples five minutes after READY and sums the platform-native RSS of Main, Utility, and Renderer without subtracting Electron Framework pages resident in multiple processes. The limit is 560 MiB: the macOS arm64 reference package measures 532.4 MiB p95 while its three-process physical footprint totals about 324 MiB, leaving approximately 5% RSS variance without replacing the cross-platform metric with a platform-specific footprint statistic. Installed-data acceptance submits twenty 5 MiB images through Renderer, Main, and Utility, persists twenty objects, and requires the three-process peak RSS increase over the settled baseline to stay within 300 MiB; the reference installed build measures 272,711,680 bytes. Disk staging, admission-time 480px WebP derivatives, disabled libvips caching, viewport-lazy thumbnails, purpose-aware URL caching, and on-demand originals are the owned mechanisms behind this limit.

Structured logs admit only stable codes and numeric lifecycle fields, rotate by size, and use owner-only files. Diagnostic export reconstructs a new ZIP from an allowlist after user confirmation; it never copies raw logs blindly and excludes credentials, environment variables, session/model text, workspace/plugin content, and absolute paths.

## Alternatives considered

**Run the Host in Main.** This removes one process and one bridge, but plugin or native work can block/crash the window authority, and Renderer input reaches the same process that holds filesystem, update, and navigation privileges. It also makes clean Host restart inseparable from application restart.

**Use a hidden localhost WebServer.** Reusing HTTP/WebSocket reduces IPC code but creates a listening socket, port/authentication lifecycle, browser-origin exposure, and another path around sender/generation checks. The transport-neutral dispatcher and explicit carrier keep shared protocol behavior without that authority.

**Expose generic invoke/send/on through Preload.** A generic bridge lets Renderer select channels or payloads that Main did not intentionally grant. A closed schema evolves with versioned commands and makes every privilege reviewable.

**Let Main own the Host lease.** Main can remain alive while Utility has failed or has not mounted persistence, so its lock would not prove the actual writer exists. Utility ownership aligns lease lifetime with business writes and lets CLI/Web use the same primitive.

**Retry mutations after Utility restart.** It can duplicate an operation that crossed the process boundary before failure. Outcome unknown plus baseline reconstruction preserves at-most-once submission rather than guessing.

**Publish installers from one cross-compiling runner or sign after verification.** Native ABI, helper signing, installer behavior, and notarization are properties of target-specific final bytes. Native protected builds and post-sign verification keep the tested artifact identical to the release candidate.

**Use application-managed Linux auto-update.** Cross-distribution replacement would bypass the package manager that owns dependencies, permissions, and uninstall. Linux therefore receives explicit external upgrade guidance.

## Consequences

- Main stays small enough to audit but must supervise a real Utility protocol, generation registries, and bounded teardown rather than calling Host methods directly.
- A Utility failure can recover without discarding a healthy Renderer, and a Renderer failure can replace the window without terminating a healthy Host; stale process artifacts have no authority in the new generation.
- The exclusive home lease protects shared durable state across products, at the cost that users cannot run two Host writers against one `DSH_HOME`.
- Native package evidence is inherently a four-runner release concern. Local unsigned packaging validates closure, ASAR/fuses, native loading, process wiring, and materials but cannot claim platform signing, notarization, update-feed availability, or stable publication.
- Release reliability checks increase protected-CI duration. The four-target 60-minute endurance matrix and 20-cold/20-warm startup performance samples run only for a manually requested release, not ordinary pull requests, while matrix aggregation treats either failure as a release failure.
- Logs and diagnostic bundles trade arbitrary debugging detail for a reviewable privacy guarantee; support requests use stable codes and user-reviewed artifacts instead of a full home copy.
- The [GUI layering/RPC note](2026-07-19-gui-layering-and-rpc-protocol.md), [Web transport note](2026-07-24-web-config-tree-boot-and-transport-layering.md), and [shared GUI carrier note](2026-08-16-shared-gui-composition-and-explicit-carrier.md) remain active: this decision realizes their extension points but does not replace their protocol, Web, or shared-composition rationale.
